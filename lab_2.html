    1. ¿Qué es Metasploit?

    Metasploit Framework es un framework de código abierto para pruebas de penetración (pentesting) mantenido por Rapid7. Es la herramienta de explotación más usada del mundo de la seguridad ofensiva: contiene miles de módulos de explotación, payloads, codificadores y módulos auxiliares (escáneres, fuzzers, sniffers…), además de herramientas para el trabajo post-explotación.

    Uso legal: Metasploit solo debe usarse contra sistemas para los que tengas autorización explícita por escrito (laboratorios propios, CTFs, programas de bug bounty o contratos de pentesting). Usarlo contra terceros sin permiso es un delito en la mayoría de jurisdicciones.

    2. Interfaces y componentes

    • msfconsole — consola interactiva principal (la que simula el laboratorio de la otra pestaña).
    • msfvenom — genera payloads standalone (ejecutables, shells de una línea, etc.) fuera de la consola.
    • msfbd / Metasploit Pro — versión comercial con GUI, campañas y reportes.
    • Arkal data/ y modules/ — los módulos se organizan en exploits/, auxiliary/, post/, payloads/ y encoders/.

    3. Flujo de trabajo típico

    1. Reconocimiento — nmap, Nessus o módulos auxiliares de escaneo (auxiliary/scanner/*) para identificar servicios y versiones vulnerables.
    2. Búsqueda del módulo — search por CVE, nombre o plataforma.
    3. Selección — use para cargar el exploit.
    4. Configuración — revisar show options y asignar RHOSTS, LHOST, PAYLOAD, etc.
    5. Verificación y explotación — check (si el módulo lo soporta) y exploit o run.
    6. Post-explotación — Meterpreter: recopilación, escalada, persistencia, pivoting.
    7. Documentación — registrar cada paso y hallazgo; es clave en un pentest real.

    4. Comandos esenciales de msfconsole

    Navegación y ayuda

    • help — lista de comandos disponibles.
    • search <término> — busca módulos (admite filtros como type:exploit, platform:windows, cve:2017-0144).
    • use <módulo> — carga un módulo; back sale de él.
    • info — descripción, referencias y opciones del módulo actual.
    • show options / show advanced / show payloads — enumera parámetros.

    Configuración

    • set <OPCIÓN> <valor> — asigna un valor; unset lo borra.
    • setg / unsetg — variables globales persistentes entre módulos.
    • set PAYLOAD <ruta> — elige el payload (ej. windows/x64/meterpreter/reverse_tcp).
    • save — guarda la configuración actual.

    Ejecución

    • exploit o run — lanza el módulo.
    • exploit -j — lo lanza como tarea en segundo plano (job).
    • check — comprueba si el objetivo parece vulnerable sin explotar.
    • jobs / kill <id> — gestiona tareas en curso.
    • sessions -l / sessions -i <id> — lista e interactúa con sesiones abiertas.

    5. Payloads: tipos principales

    • Singles / inline — todo en un payload (ej. windows/x64/shell_reverse_tcp); más pequeños pero sin staging.
    • Stagers — establecen el canal y descargan el stage (ej. reverse_tcp, bind_tcp, reverse_https).
    • Stages — el payload final (ej. meterpreter), enviado por el stager.
    • reverse_tcp — la víctima conecta hacia ti (atraviesa NAT/firewall del lado víctima); bind_tcp — conectas tú hacia un puerto abierto en la víctima.
    • meterpreter — payload avanzado en memoria, con su propio conjunto de comandos y mayor sigilo.

    6. Meterpreter (post-explotación)

    • sysinfo, getuid, getpid — información de la máquina y del contexto actual.
    • ps / migrate <pid> — listar procesos y migrar la sesión a otro proceso (por ejemplo, a uno estable como explorer.exe).
    • hashdump — vuelca los hashes SAM (requiere SYSTEM).
    • shell — cae a una cmd normal del sistema.
    • upload / download — transferencia de archivos.
    • screenshot, keyscan_start, webcam_snap — espionaje (solo con autorización).
    • portfwd, route add — pivoting hacia redes internas.
    • getsystem — intenta escalada a SYSTEM (técnica histórica; hoy suele fallar en sistemas parcheados).
    • background — devuelve la sesión a segundo plano sin cerrarla.

    7. Módulos auxiliares y base de datos

    • Escáneres: auxiliary/scanner/portscan/tcp, auxiliary/scanner/smb/smb_version, etc.
    • Fuzzing, servers falsos (auxiliary/server/capture/*), spoofing (auxiliary/spoof/*).
    • Con PostgreSQL: db_status, workspace, hosts, services, creds, vulns — guardan y consultan los resultados del pentest.

    8. msfvenom (generación de payloads)

    • Sintaxis: msfvenom -p <payload> LHOST=<ip> LPORT=<puerto> -f <formato> -o <archivo>.
    • Formatos comunes: exe, dll, elf, python, raw, bash.
    • Codificación y evasión: -e x86/shikata_ga_nai -i 3 (útil para entender conceptos; los antivirus modernos detectan lo básico).
    • Listar: msfvenom --list payloads / --list formats.

    9. Buenas prácticas

    • Verifica siempre RHOSTS antes de lanzar un exploit: un error puede tirar el servicio del objetivo.
    • Usa check cuando esté disponible para validar la vulnerabilidad sin causar daño.
    • Prefiere reverse_https o reverse_tcp con set ExitOnSession false + exploit -j para sesiones múltiples.
    • Documenta: notes, loot, y capturas de pantalla de cada paso.
    • Mantén el framework actualizado (apt o msfupdate): los módulos cambian constantemente.
